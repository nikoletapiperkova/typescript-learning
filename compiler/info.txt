1. Why Node.js Code Fails in the Browser (CommonJS)
The Problem: When configured for Node.js ("module": "commonjs"), 
TypeScript compiles imports into require() statements (e.g., const app2 = require("./app2")).

The Error: Browsers will throw Uncaught ReferenceError: require is not defined.

The Reason: require() is a built-in Node.js function designed to read files
 directly from the local hard drive. Due to security sandboxing,
  web browsers do not have this capability or function.


2. Why Native Browser Code Works (ES Modules)
The Requirement: To run code natively in modern browsers (using <script type="module">), 
you must use ES Modules ("module": "es6" or higher in tsconfig.json).

The Behavior: TypeScript preserves the standard import syntax, 
but requires explicit file extensions (e.g., import { Monkey } from "./app2.js").

The Reason: Modern browsers natively understand these 
import statements and can automatically fetch the required files from the server via HTTP.

Source maps are special files that bridge the gap between the code you write 
(TypeScript, modern JavaScript, SASS) and the code that actually runs in the browser 
(minified, bundled, or compiled JavaScript/CSS).

They are essentially a translation guide for your browser's developer tools.
